视觉设计
配色 · 排版 · 间距
高 Emoji 作为功能图标（P0 违规）
index.html:25,52,78,115  |  style.css:660
favicon 使用 📰、Logo 使用 📰、主题切换按钮使用 🌙、空状态使用 📰。这些 emoji 作为 UI 功能图标， 在不同设备上渲染不一致，且不可矢量缩放、不可着色。违反 P0 绝对规则。
改进方向：统一替换为内联 SVG 图标方案。favicon 用 SVG + <text> 改为 <path> 绘制的报纸/地球图标；Logo 用 SVG 新闻图标 + 文字 "TechNews"；主题切换用太阳/月亮 SVG； 空状态用大型 SVG 插画或图标。所有图标统一描边宽度 1.5px，尺寸 16/20/24px。
高 大量硬编码颜色值未使用 CSS 变量
style.css:521,525,530,534,539,543,672,913-997,1410-1425 等 30+ 处
CSS 中存在 30+ 处硬编码 hex 颜色值（#3b82f6, #8b5cf6, #ef4444, #16a34a, #64748b 等），散落在平台标签、状态徽章、统计图表中。 主题切换时这些颜色无法跟随变化，导致暗色模式下部分元素对比度不足。
改进方向：在 :root 和 [data-theme="dark"] 中补充平台色变量： --color-hackernews, --color-bilibili, --color-status-success, --color-status-error, --color-status-info 等。所有硬编码颜色替换为 var(--xxx)。 当前: → 应为:
中 最小字号 0.7rem（~11.2px）偏小
style.css:436,445,504,515 等
平台标签、时间戳、分页信息等使用 0.7rem(~11.2px) 和 0.72rem(~11.5px) 字号。 在 1080p 显示器上勉强可读，在低分辨率或高 DPI 屏幕上会模糊。WCAG 建议最小可读字号不低于 12px。
改进方向：将 0.7rem → 0.75rem(12px)， 0.72rem → 0.8rem(12.8px)，0.78rem → 0.8rem。 统一最小字号为 0.75rem（12px），仅在非关键辅助信息上使用。
中 缺少 CSS 变量统一管理间距和圆角
style.css 全局
border-radius 散用 6px/8px/10px/12px/16px 等 5 种值，padding 和 gap 也缺乏统一规范。视觉上不够一致，修改时需要全局搜索替换。
改进方向：定义间距 Token：--radius-sm: 6px; --radius-md: 10px; --radius-lg: 16px; 定义间距：--space-1: 4px; --space-2: 8px; --space-3: 12px; --space-4: 16px; --space-6: 24px; 全局替换为变量引用。
低 admin.html 资源版本号不一致
admin.html CSS/JS 引用  |  ASSET_VERSION = 6
首页使用 ?v=6，但 admin.html 仍使用 ?v=2，可能导致浏览器使用过期缓存。
改进方向：统一所有 HTML 模板的资源版本号为 ?v={{ ASSET_VERSION }}，通过 Flask 模板变量注入。
低 admin-blog.html 编辑器工具栏按钮缺少样式类
admin-blog.html  |  style.css: .toolbar-btn
CSS 中定义了 .toolbar-btn 样式类，但 HTML 中的工具栏按钮未添加该类名，导致编辑器按钮样式降级。
改进方向：给所有编辑器工具栏 <button> 添加 class="toolbar-btn"。
2
用户体验
导航流畅度 · 信息架构 · 交互反馈
高 博客详情页存在 XSS 漏洞
blog-detail.js: renderArticle()  |  blog-detail.html
blogDetailContent.innerHTML = post.content 直接将后端返回的 HTML 原样注入 DOM。 如果博客内容中包含恶意 <script> 标签或 onerror 事件，将导致 XSS 攻击。 虽然当前仅管理员可发布博客，但这是安全隐患。
改进方向：后端入库时使用 HTML 净化（如 Python 的 bleach 库，白名单允许 <p>, <a>, <code> 等安全标签）。前端渲染时配合 DOMPurify 做二次防护。
高 主题切换逻辑在 5 个 JS 文件中重复实现
app.js, blog.js, blog-detail.js, admin.js, admin-blog.js
主题切换（读取 localStorage、设置 data-theme、监听按钮点击、检测 prefers-color-scheme）的逻辑 在 5 个 JS 文件中各写了一遍，代码重复约 200 行。一旦修改需要同步 5 处，极易遗漏。
改进方向：抽取 theme.js 公共模块，所有页面引入。使用 ES Module export 导出 initTheme() 函数，各页面调用即可。减少维护成本。
中 主题切换按钮在不同页面显示不一致
index.html:78 vs blog.html / blog-detail.html / admin-blog.html
首页主题切换按钮内容为 🌙（emoji），博客页面为文字 "Dark"。用户在页面间跳转时 感官不一致，产生割裂感。
改进方向：统一为 SVG 月亮/太阳图标 + aria-label="切换亮色/暗色主题"。 JS 中根据当前主题切换显示太阳或月亮图标。
中 导航信息架构不完整
index.html header  |  blog.html / blog-detail.html / admin-blog.html header
首页导航有"全部/GitHub/HN/Bilibili/Blog"分类标签 + 博客链接 + 后台链接，但博客页面只显示 "资讯"和"博客"两个链接，后台管理页面没有返回前台的导航。用户在后台页面无法快速回到首页。
改进方向：所有页面统一导航栏结构：Logo（可点击回首页）+ 核心导航（资讯/博客）+ 管理入口。后台页面增加"返回前台"链接。保证用户在任何页面都能 1 步回到首页。
中 搜索/筛选时缺少加载状态反馈
app.js: searchArticles() / blog.js: loadPosts()
用户输入搜索词或切换分类后，页面无任何加载指示（骨架屏/loading spinner），内容直接替换。 在网络较慢时用户不知道是否在加载，体验突兀。
改进方向：请求发起时在内容区域显示骨架屏（skeleton screen）或半透明遮罩 + spinner。请求完成后淡入新内容。
中 热门文章横向滚动体验粗糙
index.html hot-section  |  app.js: hot scroll
热门文章区域用 prev/next 按钮控制横向滚动，但在移动端没有触控滑动支持，按钮在小屏幕上也不够直观。 且滚动步长固定，可能在某些屏幕宽度下露半截卡片。
改进方向：移动端改用 overflow-x: auto; scroll-snap-type: x mandatory; 实现原生触控滑动 + 卡片对齐。保留按钮在桌面端，移动端隐藏。添加 scroll-behavior: smooth。
低 Toast 通知缺少自动消失动画
style.css: .toast  |  app.js
Toast 通知出现和消失是硬切（display 切换），没有过渡动画，视觉上较生硬。
改进方向：添加 opacity + transform: translateY() 过渡动画， 使用 transition: all 0.3s ease。
3
性能表现
加载速度 · 资源优化
高 CSS 和 JS 均未压缩，传输体积偏大
style.css (32KB)  |  app.js (20KB)  |  admin.js (301行)
style.css 32KB 未压缩，app.js 20KB 未压缩。首次加载体积约 60KB+ （含 HTML），在弱网环境（3G/4G）下首屏时间可达 2-3 秒。
改进方向：引入构建步骤（如 esbuild/terser），对 CSS 和 JS 做 minify。 或者用 Flask Response(gzip_content, headers={'Content-Encoding': 'gzip'}) 服务端开启 gzip。 预期压缩后 CSS ~8KB、JS ~6KB，减少 60% 传输。
中 每页加载独立 JS 文件，无法复用缓存
index.html -> app.js  |  blog.html -> blog.js  |  admin.html -> admin.js 等
5 个页面各加载独立 JS 文件，主题切换等公共逻辑重复编写。用户从首页跳到博客页需要重新下载 blog.js，其中重复的主题切换代码也会重新下载。
改进方向：抽取 common.js（主题/导航/工具函数），各页面只加载 页面专属 JS + common.js。common.js 可被浏览器缓存，跨页面复用。
中 无图片懒加载
app.js: renderArticleCard()
文章卡片目前不展示图片缩略图（纯文字），但如果后续添加图片，缺少懒加载机制会导致首屏加载大量图片。
改进方向：预留 loading="lazy" 属性在 <img> 标签上。 或者使用 Intersection Observer API 实现更精细的懒加载控制。
低 CSS 中 @media 查询分散在文件多处
style.css:406,1031,1060,1644,1654
响应式 @media 查询散落在 CSS 文件 5 个不同位置，未集中管理。修改移动端样式时 需要在文件中来回跳转。
改进方向：采用移动优先策略，将 @media 查询集中到文件末尾， 或拆分为 base.css + responsive.css。

内容质量
文案清晰度 · 信息完整性
高 meta 描述信息过时，缺少 Bilibili 和 Blog
index.html:4,9,13,19  |  footer 文字
<meta description> 仍写 "YouTube、TikTok、GitHub"，但实际已有 5 个数据源 （GitHub/HN/Bilibili/Blog + YouTube 超时）。OG 和 Twitter Card 同样过时。Footer 也未列出 Bilibili 和 Blog 来源。搜索引擎和社交分享展示的信息与实际不符。
改进方向：更新所有 meta 描述为 "聚合 GitHub、Hacker News、Bilibili、科技博客等 平台的实时科技资讯"。Footer 同步更新数据源列表。OG 描述保持 160 字符以内。
中 博客详情页缺少独立 meta 描述
blog-detail.html: meta description
博客详情页使用通用 "TechNews 博客文章详情" 描述，未根据文章内容动态生成。 搜索引擎无法获取有效摘要，社交分享时也只显示通用描述。
改进方向：后端在渲染 blog-detail.html 时，将文章 excerpt 注入 <meta name="description"> 和 OG 标签。前端 JS 加载文章后也动态更新 document.querySelector('meta[name=description]')。
中 文章卡片缺少内容来源标注
app.js: renderArticleCard()
文章卡片显示了平台标签（GH/HN/BL/BG/YT），但没有标注数据来源时间（"采集于 2 小时前"）。 用户无法判断信息时效性，对于科技资讯类网站这是关键信息。
改进方向：在卡片底部添加 "采集时间" 或 "来源发布时间"（文章已有 published_at 字段），格式化为相对时间（如 "3 小时前"、"昨天"）。
低 空状态文案缺少引导性
app.js: empty-state  |  admin-blog.js: empty state
首页无文章时显示"暂无文章"，但没有告诉用户接下来可以做什么（等待爬虫抓取？手动触发？）。 博客管理空状态显示"选择或创建一篇文章"，但缺少"新建文章"的快捷按钮。
改进方向：空状态增加操作引导。首页："暂无文章，正在从各平台抓取中..." 或添加"手动刷新"按钮。博客管理："还没有文章，点击这里创建第一篇" + 按钮。
5
移动端适配
响应式布局 · 触控体验
高 缺少平板尺寸断点（768px-1024px）
style.css @media: 480px, 768px, 900px
响应式断点只有 480px（手机）和 768px（平板/小桌面），但 768px 到 1024px 之间的平板横屏 和小笔记本没有专门适配。文章卡片在这一区间可能显示为 2 列但间距过大，或 3 列但过于拥挤。
改进方向：增加 @media (max-width: 1024px) 断点，平板横屏显示 2 列。 调整断点体系为：480px（手机竖屏）/ 768px（平板）/ 1024px（小桌面）/ 1280px+（桌面）。
中 移动端导航标签可能溢出
style.css:1063  |  index.html nav-tabs
768px 断点下导航标签设为 font-size: 0.75rem; padding: 8px 12px; min-height: 44px， 但有 5 个标签（全部/GitHub/HN/Bilibili/Blog），在 360px 宽的手机上可能需要横滑才能看到全部。 当前没有 overflow-x: auto 设置。
改进方向：在 480px 断点下给 .nav-tabs 添加 overflow-x: auto; -webkit-overflow-scrolling: touch; white-space: nowrap;。 或在移动端改为下拉选择器。
中 热门文章区域移动端体验差
style.css: hot-section responsive  |  app.js
热门文章横向滚动区域在移动端没有适配为触控滑动，仍依赖 prev/next 按钮。 按钮在 360px 屏幕上占用空间大，卡片可视区域仅剩约 240px，体验局促。
改进方向：768px 以下隐藏 prev/next 按钮，改为 overflow-x: auto; scroll-snap-type: x mandatory; 原生触控滑动。 卡片宽度设为 min-width: 85vw，一次只看一张。
中 博客后台编辑器移动端不可用
style.css:1644 @media (max-width: 900px)  |  admin-blog.html
博客管理页面采用左右分栏布局（列表+编辑器），900px 以下改为上下堆叠。但编辑器工具栏按钮 和文本区在手机上太小，无法舒适操作。编辑器场景本身不适合移动端，但至少应可查看。
改进方向：移动端隐藏编辑器面板，只显示文章列表 + "在桌面端编辑"提示。 或者提供简化版的 Markdown 编辑器（纯文本输入 + 预览），替代复杂 HTML 工具栏。
低 缺少 viewport 手势缩放禁用策略
所有 HTML 模板: meta viewport
所有页面 viewport 为 width=device-width, initial-scale=1.0，允许用户双指缩放。 这对可访问性是好的（WCAG 要求），但可能导致表单聚焦时 iOS 自动放大。建议但不强制。
改进方向：保持当前设置（不禁用缩放，符合 WCAG）。如有表单聚焦放大问题， 用 font-size: 16px 解决（iOS Safari 在 16px 以上不会自动放大）。
6
可访问性
对比度 · 键盘导航 · 语义化标签
高 暗色模式下部分元素对比度不达标
style.css:913-997 暗色模式平台标签
暗色模式下，平台标签文字使用 #93c5fd（浅蓝）on #1e293b（深蓝背景）， 对比度约 4.8:1，勉强通过 WCAG AA（要求 4.5:1）。但 #6ee7b7（浅绿）和 #fca5a5（浅红）在相同背景上对比度更低，约 3.5:1，不达标。
改进方向：使用 WebAIM Contrast Checker 逐对验证。将 #6ee7b7 调亮为 #86efac（已有但未统一使用），#fca5a5 调亮为 #fecaca。 确保所有文字+背景组合达到 WCAG AA 4.5:1。
中 文章卡片缺少语义化 landmark
app.js: renderArticleCard()
文章卡片渲染为 <article> 标签（好），但没有 <h3> 标题层级。 卡片标题用 <a> 包裹但不是 heading 元素，屏幕阅读器无法按标题导航。
改进方向：文章卡片标题包裹 <h3>： <h3><a href="...">标题</a></h3>。保持 heading 层级： h1(页面标题) → h2(区块标题) → h3(卡片标题)。
中 博客详情页内容缺少 ARIA 标记
blog-detail.html: #blogDetailContent
博客详情内容容器 #blogDetailContent 没有 role="article" 或 aria-label。屏幕阅读器用户无法快速定位到文章主体。
改进方向：添加 <article role="article" aria-labelledby="blogTitle">。 确保文章标题有 id="blogTitle" 供 ARIA 引用。
中 分页按钮缺少 aria-current 标记
app.js: renderPagination()
分页组件中当前页码虽然有 class="active" 样式区分，但缺少 aria-current="page" 属性。屏幕阅读器用户无法知道当前在第几页。
改进方向：在当前页码按钮上添加 aria-current="page"， 并添加 aria-label="第 N 页（当前）"。其他页码添加 aria-label="第 N 页"。
低 skip-link 已实现但仅首页有
index.html: skip-link  |  blog.html / blog-detail.html / admin.html
首页有 skip-link（"跳转到主要内容"），但博客列表、博客详情、管理后台页面缺少。 键盘用户在这些页面需要 Tab 多次才能到达主内容。
改进方向：所有页面模板统一添加 <a href="#mainContent" class="skip-link"> 和 <main id="mainContent">。一行代码的事，但大幅改善键盘体验。
低 :focus-visible 样式已实现但部分交互元素遗漏
style.css: :focus-visible  |  editor toolbar buttons
CSS 中有 :focus-visible 全局样式（好），但编辑器工具栏按钮和分页按钮 可能被 outline: none 覆盖。需要确认所有可交互元素都有可见的焦点指示。
改进方向：全局搜索 outline: none，每处确认是否提供了替代的 :focus-visible 样式（如 box-shadow）。没有的补上。
